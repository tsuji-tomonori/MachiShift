## 暫定初期値

Three.jsとRapierを使い、原典からの地理・表示・衝突をゲーム追加物およびレース状態から分離しました。地理・物理状態・UI走行・QAで実際に分担して統合し、原典ベンチ/外壁の塗装破壊、実道路上の6台3周、原典保持と実資源の解放・復元を実行しました。3D画面を操作するプレイ確認は未完了です。

## 残す判断

| ID | 判断 | 決めるための材料 | 現在の初期値・制約 |
|---|---|---|---|
| DEC-01 | PCブラウザーを最終対象にするか | 指定負荷での実機計測、近景と破壊の品質 | PCブラウザーで続行。性能不足だけを理由に無断でネイティブ専用化しない |
| DEC-02 | 初版の破壊対象 | 実在設備・外装の資料、分割と物理の検証 | 街路設備＋一部外装を維持。未収録設備を架空の実在物にしない |
| DEC-03 | 地理の基準時点 | 元の撮影・測量年、公開年と補修記録 | データごとの確認可能な年月を表示。不明年は不明とする |
| DEC-04 | 現地写真・寸法確認の時間と予算 | 地物ID付き10断面・20地点と写真の収集リスト | 未測量部分の精度要件を残し、必要な収集量を具体化する |
| DEC-05 | 正確なAOI・ルート・デッキ利用 | 加工後のデータ、実道路幅、地上/デッキの現実の接続 | 地上中心。接続未確認のデッキをコースに含めない |

実際のAOI選択矩形は0.5184km²、路面に対応するコース長は1,388.202mとなった。約0.3〜0.5km²の目標に対する差と、現地確認後の最終境界確定を残す。原典年度2024と、その属性ごとに異なる測量・撮影年を同じ意味にしない。

台数削減、舞台変更、道路の拡幅、精度・性能・破壊要件の緩和は既定の判断に含めません。必要になった場合は元要件と代替検証の結果を示します。

## 再開する順序

1. `docs/acceptance.md` と要件台帳の非PASS行、直近の実行ログを読む。
2. 同じブランチの依存を `npm ci` で導入し、型検査・状態試験・ビルド・要件整合性を実行する。
3. `docs/geodata.md` のコマンドと出典台帳で加工データを再現する。原典の不変ハッシュを確認する。
4. 実行済みの物理証跡と初回カーブの接触診断を読み、残る走行品質・縁の塗装・走行中破片の応答を検証する。実ブラウザーで中核試験と3周、結果、再レース、自由走行を行う。
5. 未取得の独立資料・実機・人の評価を用意してGate Dを検証する。全必須行に完全な証跡が揃ってから総合完了を判定する。

作業ブランチとPRを成果物にします。原プロンプト11章の指定に従い、自動マージ・本番公開・有料インフラ作成は別の明示指示がない限り実行しません。

## 現在の外部実行上の制約

空のGitHubリポジトリへ初期mainを作る操作は、作業ブランチとPRを使う方針を理由に自動承認レビューが拒否した。featureブランチのGit送信もUsername認証情報がなく失敗した。リモートの作業ブランチ、PR、CIは存在を確認できる成果物に含めない。初期main作成に関する明示的な承認を得た後、利用可能なGitHub APIでブランチ・PR・CIへ進む。

Work cloud ChromeはWebGLが無効で、エラーと再試行画面まで確認した。異なるローカルブラウザー制御へ切り替えて制約を迂回しない。実装済みE2Eを実行できるCI、またはWebGL2が有効なPCでプレイを検証する。実GPU・実ゲームパッド・初見の人の評価・独立測量はそれぞれ別の必要条件である。
